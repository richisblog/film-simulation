# Dazz 相机滤镜与漏光资料库设计

## 目标

在现有 Film Simulation PWA 中加入从 Dazz Camera 2.17.4 恢复的相机级色彩配方与漏光素材，保持原有 36 个滤镜的数据、顺序和行为不变，并用清晰的分隔和两级导航将两套资料库完全区分。

## 滤镜信息架构

滤镜区保留“经典胶片 · 36”作为第一组。其后增加视觉上明确的横向分隔栏与“DAZZ CAMERA · N”标题。Dazz 使用两级选择：一级是相机族，二级是该相机的成片配方。只有一个配方的相机点击后直接选中；拥有多个配方的相机展开紧邻的二级配方条，并记住该相机最后选中的配方。

配方显示名使用“相机名 · 配方名”，例如 `FXN · Original`、`FXN · FXN2`、`DAM · A709`。界面不直接暴露 `lookup_*`、Light、Color、Mask、Raw 等内部实现名。

所有已确认的成片配方都纳入。单级相机直接使用其色彩 LUT；OFM、FQS、PAF 等多级相机按反汇编确认的阶段顺序离线合成为一个成片 LUT。Mask、Raw 和仅供内部处理中间步骤使用的资源不单独成为卡片。

## 色彩资源管线

Dazz 资源放在独立的 `public/assets/dazz/luts/` 目录和独立 manifest 中，不修改原 36 个滤镜的 manifest。构建脚本读取恢复后的标准 CUBE，生成：

- 低阶预览 LUT，用于相机和配方缩略图；
- 高精度成片 LUT，仅在用户选择该配方时加载；
- 相机族、配方、中文名、英文名、合成阶段和资源长度元数据。

多级配方通过对恒等色立方体依次应用各阶段 LUT 后重新采样，生成单个浏览器可用 LUT，避免运行时多次查表。Dazz LUT 使用独立缓存版本，失败时沿用现有重试与错误提示机制。首次打开页面不预载全部高精度 Dazz LUT。

## 漏光信息架构

漏光区保留“原有漏光 · 20”，随后增加分隔栏并加入：

- “Dazz 通用漏光 · 17”：`lightleaks1.jpg` 至 `lightleaks17.jpg`；
- “Dazz Instant 漏光 · 10”：`lightleaks_inst_01.jpg` 至 `lightleaks_inst_10.jpg`。

`flashc_*.jpg` 等展示样片不作为漏光。27 个 Dazz JPEG 离线转换为 WebP，保留原构图与色彩。所有漏光共用现有的关闭、强度、旋转和翻转控制，资源清单记录来源分组，界面不将 47 个素材混成无分区列表。

## 交互与响应式布局

桌面端中，两套滤镜分别使用网格；Dazz 相机一级网格下方显示当前相机的配方网格。移动端一级相机横向滚动，配方条紧邻显示并独立横向滚动。单配方相机不会制造空的二级菜单。

选择 Dazz 配方后，预览、导出、匿名滤镜导出统计和状态恢复都使用稳定配方 ID。语言切换同时更新分组标题、相机/配方名称和无障碍标签。原有滤镜 ID 保持不变。

## 组件边界

- Catalog：分别加载经典 LUT、Dazz 相机 manifest 和两类漏光 manifest，并按组暴露描述符。
- Dazz recipe builder：离线生成单级或多级成片 LUT、预览 LUT 和确定性 manifest。
- Filter browser：渲染经典分组、分隔栏、Dazz 相机一级菜单与配方二级菜单。
- Leak browser：渲染关闭按钮、原有漏光、Dazz 通用漏光和 Dazz Instant 漏光。
- Editor state：保存当前配方 ID和每台 Dazz 相机最近使用的配方，不改变图像处理设置接口。

## 错误处理

manifest 缺失、资源长度不符、CUBE 维度不合法或多级配方阶段不存在时，构建/测试立即失败。浏览器加载失败时保留当前照片和设置，通过现有错误提示提供重试。某个 Dazz 缩略图失败不阻止经典 36 个和其他 Dazz 相机继续使用。

## 验收标准

- 原有滤镜数量严格为 36，顺序和 ID 不变。
- 所有确认的 Dazz 成片配方都有唯一 ID、相机归属、双语名称与可加载资源。
- 多配方相机显示二级菜单，单配方相机直接选择。
- Light/Color 多级配方生成一个成片 LUT，阶段顺序有自动测试。
- 漏光数量严格为 20 + 17 + 10，三个分组标题与分隔可见。
- 桌面和移动端均能选择 Dazz 配方、调整漏光、导出图片并切换语言。
- 构建、单元测试、资源测试和 Playwright 关键流程全部通过。
